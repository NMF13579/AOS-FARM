# Установка AOS-FARM (Installation)

Это обзорный документ о том, как устанавливается AOS-FARM.

Основное руководство по установке и переносу находится здесь: [INSTALL-AND-TRANSFER.md](INSTALL-AND-TRANSFER.md).

## Сухая проверка (Dry-Run)
*Реализовано (MVP)*

Перед тем как переносить файлы, необходимо выполнить "сухую проверку". Это покажет, что именно будет добавлено в ваш проект, без реального изменения файлов.

Команда для запуска:
`python3 aos/scripts/aos_install.py --dry-run`

**Важное замечание по структуре папок:** Перед тем как в будущем применять какие-либо изменения установщиком, убедитесь, что вы понимаете [Модель границ рабочего пространства (Workspace Boundary)](WORKSPACE-BOUNDARY.md), и обязательно прочитайте [Руководство по первому запуску (AOS First Start Guide)](FIRST-START.md). Установщик не будет работать с папкой `/project/` как с кодом продукта, а временная директория `/.aos-tmp/` никогда не должна использоваться для важных отчетов.

Dry-run:
* Находит корень репозитория и `/aos/root/`.
* Строит план разворачивания (mapping: `/aos/root/<relative-path>` -> `/<relative-path>`).
* Обнаруживает конфликты (если целевой файл уже существует, например `README.md`, `llms.txt`, `AGENTS.md`).
* Конфликты обрабатываются как `HUMAN_REVIEW_REQUIRED` (не перезаписываются молча).
* Запрещает создание директорий с исходным кодом внутри `/project/` (например, `src`, `tests`).
* Запрещает пути, выходящие за пределы корня или указывающие в `.git/` / `/.aos-tmp/`.
* **Ничего не изменяет в файловой системе.**
* Возвращает статусы: `PASS` / `PASS_WITH_WARNINGS` / `HUMAN_REVIEW_REQUIRED` / `BLOCKED` / `UNKNOWN_BLOCKED`.

**ВАЖНО:** Dry-run `PASS` не является approval.

## Установка (Apply)
*Статус: РЕАЛИЗОВАН БЕЗОПАСНЫЙ РЕЖИМ (Safe Apply MVP)*

Команда для применения установки:
`python3 aos/scripts/aos_install.py --apply --safe-create-and-gitignore-append --confirm "AOS INSTALL SAFE CREATE OK" --tutor`

Этот режим строго ограничен. Он может только безопасно копировать отсутствующие файлы и аккуратно добавлять блок AOS в `.gitignore`.
Любые конфликты (существующие файлы `AGENTS.md`, `llms.txt`, `/aos/`) блокируют установку с необходимостью участия человека (`HUMAN_REVIEW_REQUIRED`).
Ручной перенос файлов по-прежнему поддерживается, как описано в [INSTALL-AND-TRANSFER.md](INSTALL-AND-TRANSFER.md).
